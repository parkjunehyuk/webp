03. WHAT IS PROMPT ENGINEERING

프롬프트 공학이란? (이란)

고차원 임베딩 공간에서 AI가 '가장 가까운 정답 좌표'를 찾도록 유도하는 입력 설계 기법

🧭 개념적 정의

LLM(대규모 언어 모델)은 확률과 벡터 유사도를 기반으로 다음 단어를 생성합니다. 입력이 모호하면 평균적인(평범한) 결과물을 내놓지만, 조건과 맥락을 촘촘히 배치하면 의도에 가장 근접한 고품질 결과물을 도출합니다.

  • 비유: FPS 게임에서 대충 쏘는 것과, 적의 위치·거리·타이밍을 계산해 정조준하는 것의 차이

🧱 프롬프트 구조화 4요소

[1. 역할 (Role)]    너는 웹프로그래밍 교수이자 시니어 개발자다.
[2. 맥락 (Context)] 소프트웨어학과 2학년 발표용 포트폴리오 제작 중.
[3. 목표 (Goal)]    오프라인 실행 가능한 단일 HTML 슬라이드 구현.
[4. 추론/형식]      단계별로 구조를 검증하고 저작권 출처를 구분하라.
04. FUNCTIONS & CHARACTERISTICS

기능: 특징 · 장점 · 단점 · 차이점 · 이용

단순 검색/질문과 엔지니어링 관점의 프롬프트 활용 비교

장점 (Pros) & 특징

  • 특징 (CoT · Few-shot): 단계별 추론(Chain of Thought)과 예시 제공으로 논리 오류 최소화
  • 장점 ① 빠른 프로토타이핑: 아이디어를 수십 분 내에 동작하는 화면으로 시각화
  • 장점 ② 맞춤형 학습 튜터: 내 코드의 오타나 버그 원인을 1:1로 분석 가능

단점 (Cons) & 이용 분야

  • 단점 ① 환각(Hallucination): 존재하지 않는 함수나 잘못된 문법을 확신에 차서 제시할 위험
  • 단점 ② 저작권 및 의존성: AI 생성 코드를 이해 없이 복붙하면 유지보수 불가
  • 이용: 코드 리뷰, 테스트 케이스 생성, UI 초안 설계, 문서 구조화
구분 일반적인 단순 질문 (Naive Prompt) 프롬프트 공학 적용 (Structured Prompt)
목표 설정 "포트폴리오 사이트 만들어줘" (모호함) 학번·과목·발표 루브릭·실행 제약조건까지 명시
사고 과정 즉답 요구로 인해 논리 비약이나 코드 누락 발생 목표 정의 $ ightarrow$ 제약 검토 $ ightarrow$ 코드 생성 순으로 추론 유도
결과물 품질 범용적이고 평범한 템플릿 출력 사용자 의도 좌표에 가장 가까운 맞춤형 결과물 도출
05. WHY USE IT?

이유: 왜 프롬프트 공학을 적용했는가?

제한된 시간 내 문제 해결과 학습 효율 극대화를 위한 현실적 선택

⏱️ 1. 제한 시간(50분) 내 구현

강의 시간 50분 안에 기획, 디자인, 발표 구조, 인터랙션 기능까지 모두 수작업으로 코딩하는 데는 물리적 한계가 있습니다. 뼈대 설계와 반복 마크업은 AI에 위임하고, 핵심 로직 검증에 집중했습니다.

🧩 2. 학습 원리의 체계적 정리

수업 중 작성한 14개의 실습 파일(시계, 퀴즈, 브라우저 판별 등)을 단순 나열하는 대신, 5가지 핵심 원리(DOM, BOM, 타이머 등)로 분류(불류)하여 제 언어로 소화하기 위해 활용했습니다.

🌉 3. AI 활용 역량 탐색

딥러닝 수식을 직접 유도하는 연구 분야는 어렵더라도, 자연어 지시를 통해 LLM의 출력을 정밀하게 제어하는 능력은 모든 소프트웨어 직군에서 필수적인 무기이기 때문입니다.

  • 브라우저·해상도 감별기: navigator.userAgent와 screen.width를 활용한 접속 환경 판별

07. CASE STUDY 02 — AI-ASSISTED PROTOTYPE

사례 ② 프롬프트 공학 실험 사례 (AI 생성물 구분 명시)

※ 저작권 및 기여도 구분: 아래 결과물은 직접 코딩이 아닌 '프롬프트 설계 실험'을 통해 LLM이 생성한 프로토타입입니다.

❄️ 실험 A: 눈 내리는 샤갈의 마을

  • 프롬프트 개입: "대학교 2학년 수준에서 이해할 수 있도록 주석을 달고 style.top 직접 수정 방식으로 단순화해줘"
  • 학습 성과: AI가 생성한 두 가지 버전(DOM 방식 vs Canvas 방식)을 비교하며 브라우저 렌더링 원리 이해

AI 생성 실험 (Reference 명시)

  • 실험 목적: 수학적 구현이 어려운 3D 원근 투영과 로그 나선 알고리즘을 자연어 명세만으로 시각화할 수 있는지 검증
  • 한계 인식: 내부 물리 수식 전체를 완벽히 통제하기 어렵다는 점을 체감
  • 결론: 내가 이해하고 설명할 수 있는 코드 범위 내에서 AI를 보조 도구로 활용해야 함을 확인
08. INSTALLATION & EXECUTION

설치 및 실행 방법 (Environment Setup)

별도 서버나 프레임워크 설치 없이 100% 오프라인·USB 환경에서 즉시 구동되는 구조

📦 1. 파일 구조 및 실행 절차

  • 1단계 (저장): 모든 HTML·CSS·JS 코드가 통합된 단일 파일(portfolio_2022564018.html) 준비
  • 2단계 (백업): 강의실 발표 대비용 USB 메모리 및 클라우드 이중 백업
  • 3단계 (실행): Chrome 또는 Edge 브라우저로 파일 더블클릭 실행 (인터넷 불필요)
  • 4단계 (조작): 키보드 좌우 방향키(← →)로 슬라이드 전환, S 키로 발표 대본 확인

🛡️ 2. 발표 시뮬레이션 체크리스트

  • 폰트 안전장치: Pretendard 미설치 PC에서도 깨지지 않도록 맑은 고딕 시스템 폰트 폴백(Fallback) 적용
  • 화면 캡처 대비: Alt + PrintScreen 캡처 시에도 글씨가 선명한 고대비 다크 테마
  • TTS & 발음 검증: 상단 🔊 TTS 미리듣기 버튼으로 발표 속도와 호흡 사전 점검
09. KEY TERMS & SUMMARY

핵심 용어 정리 & 전체 요약

발표에서 다룬 주요 개념 한눈에 보기

🔑 핵심 용어 (Key Terms)

  • DOM (문서 객체 모델): HTML 태그를 자바스크립트가 제어할 수 있는 객체로 변환한 구조
  • BOM (브라우저 객체 모델): window, navigator, screen 등 브라우저 창과 환경을 제어하는 객체
  • CoT (Chain of Thought): AI가 바로 답을 내리지 않고 단계별 추론 과정을 거치도록 유도하는 기법
  • 임베딩(Embedding): 텍스트의 의미를 고차원 벡터 좌표로 변환해 유사도를 계산하는 방식

📌 전체 요약 (Summary)

  • 자기 이해: 게임에서 익힌 정밀한 판단력을 바탕으로 기초 웹 역량을 쌓으며 진로를 탐색 중인 2학년
  • 기술 결합: 직접 코딩한 웹 실습(시계·퀴즈)과 프롬프트 공학 구조를 결합해 발표형 웹앱 구현
  • 윤리적 활용: AI 생성물과 본인 작성 코드를 명확히 구분하고 출처(Reference)를 기록하는 태도 확립
